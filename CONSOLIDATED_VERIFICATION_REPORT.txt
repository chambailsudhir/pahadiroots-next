globals.css already had `.mbn-item.active { color: var(--g) }` sitting
unused — nothing in MobileBottomNav.tsx ever applied that class, so "Home"

File: src/components/layout/MobileBottomNav.tsx

--- Gap 2 (the bigger one): three real mobile features had ZERO test coverage ---
Despite "1213/1213 tests passing" being repeated across multiple report
sections as proof of correctness, that number never actually covered:
  1. MobileBottomNav.tsx — the entire component (route suppression, cart
     badge, WhatsApp link, scroll-to-top) had no dedicated test file at all.
  2. AddToCartSection.tsx's new .pdp-mob-bar sticky bar (Fix 9) — the file
     has a substantial existing test suite, but nothing in it touched
     showMobBar/IntersectionObserver/the sticky bar's buttons.
  3. ProductGallery.tsx's new swipe gesture (Fix 10) — same situation,
     existing suite, zero swipe tests.
ROOT CAUSE: jsdom (the test environment) has no real IntersectionObserver
implementation. `new IntersectionObserver(...)` throws immediately, so any
test that tried to render these components would crash on mount — and
nobody had added a mock. Given that, "the suite passes" only proved nothing
regressed elsewhere, not that any of this new code actually works as
described. That's the "do not substitute automated verification for genuine
manual checking" pattern.

FIXED:
  - Added src/__tests__/__mocks__/intersectionObserver.ts — a shared,
    CONTROLLABLE mock (not a bare no-op stub): it captures every real
    IntersectionObserver instance and its callback, so a test can actually
    drive the intersection state and assert on what the component does in
    response, not just "doesn't crash on mount."
  - src/__tests__/MobileBottomNav.test.tsx (NEW, 19 tests): route
    suppression on /account, /checkout, and nested routes; renders on the
    homepage/listing/PDP; Home active-tab state (new); cart badge count and
    the "9+" cap; Search/Cart/Menu wiring into useUIStore; WhatsApp link
    presence and digit-stripping; scroll-to-top visibility and click
    behavior.
  - src/__tests__/AddToCartSection.test.ts (+9 tests): sticky bar hidden by
    default; appears only when the buy box's boundingClientRect.top < 0
    (scrolled past, not just "not yet scrolled to" — the exact distinction
    the component's own code draws); disappears again on scroll-back;
    price/MRP display; Add to Cart and Buy Now both wired correctly;
    out-of-stock state; observer disconnects on unmount.
  - src/__tests__/ProductGallery.test.ts (+6 tests): left/right swipe past
    the 40px threshold; sub-threshold swipe ignored; mostly-vertical touch
    ignored (scroll, not swipe); single-image gallery doesn't crash; and the
    trickiest one — a swipe doesn't also fire the tap-to-zoom lightbox via
    the synthetic click that follows touchend on real devices, but a
    genuine subsequent tap still works (the anti-double-fire flag resets
    correctly, doesn't get stuck).
